第一次处理 Crash
什么时候用：线上/测试环境出现崩溃，需要定位根因
打开率 94% 解决率 78% 更新 2026.04
预期结果
定位崩溃根因，输出修复方案或临时规避措施，崩溃率恢复正常水位
操作步骤
1
确认崩溃影响范围：版本号 / 平台 / 发生频率 / 用户占比
2
获取崩溃日志：Sentry / Firebase Crashlytics / 本地日志
3
符号化堆栈，定位到代码行号，判断是逻辑错误还是内存问题
4
本地复现：如无法复现，标记为偶现并增加日志埋点
5
输出修复方案，评估是否需要热修复，@ 技术负责人确认
常见卡点
日志符号化失败 → 检查 dSYM / mapping 文件是否匹配版本
偶现崩溃 → 增加诊断日志，监控 3 天看是否复现
涉及第三方 SDK → 先查 SDK 更新日志，确认是否已知 issue
